# 合同审批审查系统

面向企业合同审批场景的智能审查平台：从审批系统拉取待审合同 → 解析（DOCX / PDF / 扫描件 OCR）→ 条款结构化切分 → 规则引擎与 LLM 双引擎审查 → 风险清单与原文双向锚定 → 生成审查报告 → 回写审批系统评论区。

| 项 | 内容 |
|---|---|
| 当前版本 | 0.4.0 |
| 交付状态 | 阶段二演示交付（批次 1 ~ 13 已完成，见 [§14 变更记录](#14-变更记录)） |
| 运行形态 | 基础设施容器化 + 前后端原生运行（**Windows**，原因见 [§4.1 部署形态](#41-部署形态)） |
| 后端 | Python 3.12 / FastAPI |
| 前端 | Node 18+ / React 18 / Vite 5 |
| 许可证 | 未声明，见 [§15 维护信息](#15-维护信息) |

## 1. 项目简介

### 1.1 背景

企业合同审批流程中，合同文本合规性核查依赖法务人工逐条阅读：耗时长、口径不统一、审查结论不可追溯。本系统将这一环节自动化，并保留原文定位与人工复核能力。

### 1.2 目标

- **可溯源**：每个风险点必须能定位到原文页码、字符区间与可视化坐标框，不允许"结论无出处"。
- **可复核**：规则命中与模型研判分轨记录（`merged_by` 区分 `rule` / `llm` / `both`），并设防幻觉闸门拦截无原文依据的结论。
- **可闭环**：审查结论可直接回写至审批系统评论区，无需人工誊抄。
- **可维护**：审查规则与标准示范条款库支持在线增删改，规则变更即时生效且历史依据可追溯。

### 1.3 目标用户

| 角色 | 主要职责 |
|---|---|
| 法务审查人 | 核对原文高亮证据、采纳或调整修改建议、补充法务批注并触发回写 |
| 业务经办人 | 提交合同审查申请、查看风险点与整改建议、下载审查报告 |
| 系统管理员 | 配置审批系统对接参数、维护审查规则与示范条款库、处理阻塞任务重试 |

> 角色为业务语义划分，当前版本未做认证授权，详见 [§11 已知限制](#11-已知限制)。

### 1.4 交付物

| 交付物 | 位置 |
|---|---|
| 前端应用（审查大盘 / 智能审查工作台 / 合规规则与模板页） | `frontend/` |
| 后端审查服务（解析 / 审查 / 报告 / 回写） | `backend/` |
| 审批系统模拟模块（独立服务，供端到端演示） | `mock-approval/` |
| 示例合同集（5 份，含人工标注期望风险点） | `samples/` |
| 需求、设计与验收文档 | `PRD.md` / `docs/` / `ACCEPTANCE.md` |

### 2.1 文档接入与解析

- **接入方式**：大盘页「同步审批待办」从审批系统拉取附件并去重下载；或「上传合同」直接接入（`.docx` / `.pdf` / 图片）。
- **DOCX**：经 WPS COM 转为 PDF 以获得真实分页，再抽取文本与坐标。
- **PDF**：PyMuPDF 直接提取文本层。
- **扫描件 / 图片**：RapidOCR 本地 CPU 识别，字/词级框作为锚点依据；二次解析命中 Redis 缓存。
- **降级链**：WPS COM 不可用时 DOCX 走无分页降级（`docx_passthrough`），不阻断审查。

### 2.2 审查引擎

- **规则引擎**：45 条规则，覆盖 9 个风险维度；规则库使用关键词 / 阈值比较 / 存在性 / 黑名单 4 类判定方式，引擎另支持正则匹配。

| 维度 | 规则数 |
|---|---|
| 违约责任 `liability` | 10 |
| 主体资质 `subject_qualification` | 8 |
| 金额支付 `amount_payment` | 6 |
| 数据安全 `data_security` | 6 |
| 保密义务 `confidentiality` | 5 |
| 争议管辖 `jurisdiction` | 3 |
| 不可抗力 `force_majeure` | 3 |
| 验收 `acceptance` | 2 |
| 知识产权 `intellectual_property` | 2 |
| **合计** | **45**（高风险 24 / 中风险 21） |

- **规则分组**：规则按业务类型挂载，采购 14 / 销售 10 / 服务 14 / 劳动 7，各模板独立启停。
- **LLM 引擎**：`LLMProvider` 抽象，支持 `mock`（预置结论回放）与 `openai_compat`（任意 OpenAI 兼容端点）。
- **合并策略**：同一风险点取较高等级，`merged_by` 记录来源。
- **防幻觉闸门**：模型引用的原文片段无法在合同文本中定位时，风险项标记"未锚定"并交由人工核查，不静默丢弃。

### 2.3 智能审查工作台

```
+------------------------------------------------------------------------+
| 合同名称   [下载原件] [预览报告] [导出报告 v]          返回大盘        |
+------------------------------+-----------------------------------------+
| 左栏：合同正文（PDF.js）     | 右栏：风险卡片（按风险等级分组）        |
|   - 风险高亮（半透明实底）   |   - 违规原因 / 法律依据 / 风险等级      |
|   - 元数据虚线框             |   - 条款差异对比 / 复制 / 编辑 / 采纳   |
|   - 双向锚定：卡片 -> 正文   |   - 卡片 -> 正文跳转并垂直居中          |
|   - 双向锚定：正文 -> 卡片   |                                         |
+------------------------------+-----------------------------------------+
| 底部：综合风险摘要 + 法务批注 + 写回审批意见                           |
+------------------------------------------------------------------------+
```

- **视觉区分**：虚线框表示"提取到的元数据字段"，半透明实底表示"发现的风险问题"。
- **双向锚定**：卡片 → 正文自动跳页并高亮，目标位置垂直居中；正文高亮框 → 对应卡片滚动到可视区。
- **扫描件差异**：扫描件无 PDF.js 文本层，"点正文文字反查卡片"不可用，卡片 → 正文高亮正常。

### 2.4 报告与回写

- **预览报告**：拉取 Markdown 原文渲染后弹窗展示（标题 / 表格 / 引用块 / 依据链折叠），不落存储。
- **导出报告**：Markdown 与 PDF 二选一，落对象存储并下载；PDF 为精排版式（PyMuPDF Story）。
- **报告内容**：合同基本信息、综合审查结论、风险清单明细（等级 / 条款类型 / 原文定位 / 成因与依据 / 推荐示范条款）。
- **回写**：生成格式化审查意见文本写回审批系统评论区，重复调用幂等（返回 `deduplicated`）。
- **导出历史**：大盘页行内「导出记录」查看该合同的报告导出历史（大小 / 导出人 / 下载）。

### 2.5 合规规则与模板页

- **左栏合同类型**：每个模板一行并显示规则数，`编辑` 打开模板抽屉（改名 / 描述 / 启用开关）。模板停用后其下所有规则在审查中一律不加载。
- **中栏规则表**：「启用」为行内开关，修改立即生效；「条件」列展示引擎真正读取的字段。
- **规则抽屉**：按 `rule_type` 动态展开对应配置，不暴露裸 JSON；条件字段下拉仅可选引擎支持的键，避免配置无效规则。
- **保存即校验**：非法配置（编码格式、枚举值、条件字段、正则编译、关键词缺失等）返回 400 并说明原因，不写入数据库。
- **引用保护**：已被历史审查依据引用的规则禁止物理删除（返回 409，提示改用停用），保证历史报告依据可追溯。
- **标准示范条款库**：防幻觉闸门的法条白名单来源，支持在线维护。
- **主体黑名单**：只读，当前为演示数据。

## 4. 系统架构

### 4.1 部署形态

```
+---------- 原生 Windows -------------------------------------------+
|                                                                   |
|  frontend/  Vite + React + Ant Design + PDF.js        :5173       |
|      |  代理 /api 与 /health                                      |
|      v                                                            |
|  backend/   FastAPI                                   :8000       |
|      |  |-- 解析（PyMuPDF / python-docx / WPS COM / OCR）         |
|      |  |-- 审查（规则引擎 + LLM + 取高合并 + 防幻觉闸门）        |
|      |  |-- 后台任务（进程内线程 + 数据库状态机，不引入 Celery）  |
|      |  `-- 适配层 ApprovalSystemAdapter                          |
|      |                                                            |
|  mock-approval/  FastAPI 桩（扮演外部审批系统）        :8010      |
|                                                                   |
+--------------------------+----------------------------------------+
                           |                                         
+--------------------------v--- Docker Desktop · WSL2 --------------+
|  cr-mysql :13306     cr-redis :16379     cr-minio :19000          |
+-------------------------------------------------------------------+
```

**为什么后端与前端原生运行、只将基础设施容器化**：DOCX 分页依赖 WPS COM，需要交互式桌面会话，容器环境无法提供。详见 `docs/architecture.md` §5.4。

### 4.2 核心流程

```
同步待办 / 上传合同
      |
      v
  附件下载（去重）
      |
      v
  文档解析（DOCX -> PDF / PDF 文本层 / OCR） -> 失败则 blocked，可重试
      |
      v
  条款切分 + 元数据提取（记录页码、字符区间、坐标框）
      |
      v
  双引擎审查（规则引擎 + LLM） -> 取高合并 -> 防幻觉闸门
      |
      v
  风险清单落库 -> 工作台双向锚定展示 -> 法务批注与建议采纳
      |
      v
  报告生成（Markdown / PDF） -> 回写审批系统评论区
```

### 4.3 任务状态机

| 状态 | 含义 |
|---|---|
| `pending` | 待处理 |
| `parsing` | 解析中 |
| `reviewing` | 审查中 |
| `blocked` | 解析受阻（可重试） |
| `completed` | 审查完成（终态） |

回写状态：`not_written` / `writing` / `success` / `failed`。

## 6. 快速开始

### 6.1 一键启动（推荐）

在项目根目录执行：

```powershell
python scripts\start_all.py --open
```

脚本按依赖顺序执行并逐项探活：启动容器 → 建表播种 → 启动 mock 审批 / 后端 / 前端 → 打开浏览器。已就绪的环节自动跳过，可反复执行。

| 参数 | 作用 |
|---|---|
| `--open` | 启动完成后自动打开浏览器 |
| `--skip-seed` | 跳过建表与种子数据（快速重启场景） |

停止服务：

```powershell
python scripts\stop_all.py           # 只停原生服务
python scripts\stop_all.py --infra   # 连容器一起停（保留数据卷）
```

`stop_all.py` 带进程归属校验，只结束本项目进程，不会误杀占用同端口的无关进程。

### 6.2 分步启动

便于排查单点问题，按以下顺序执行。

**第一步：启动基础设施**

```powershell
docker compose up -d
docker ps        # 期望 cr-mysql / cr-redis / cr-minio 三个容器均为 healthy
```

**第二步：初始化数据库**

```powershell
cd backend
.\.venv\Scripts\python.exe -m alembic -c alembic.ini upgrade head   # 建表
cd ..
backend\.venv\Scripts\python.exe scripts\seed_data.py               # 规则库 / 示范条款 / 黑名单
```

**第三步：启动审批系统模拟服务**

```powershell
cd mock-approval
..\backend\.venv\Scripts\python.exe seed.py            # 写入演示待办（幂等）
..\backend\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8010
```

**第四步：启动后端**

```powershell
cd backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

启动时打印 MySQL / Redis / MinIO / 审批系统四项自检结果。**自检失败不阻断启动**，仍可访问 `/docs` 查看错误提示。

接口文档：<http://127.0.0.1:8000/docs>

**第五步：启动前端**

```powershell
cd frontend
npm install
npm run dev
```

访问 <http://127.0.0.1:5173>。

## 7. 使用指南

### 7.1 端到端演示流程

1. 打开大盘页，点击「同步审批待办」，系统从审批系统拉取合同并自动开始审查。
2. 等待审查状态变为「已完成」（列表自动轮询刷新）。
3. 点击合同名进入智能审查工作台。
4. 右栏点击风险卡片，左栏正文自动跳页并高亮对应条款（垂直居中）。
5. 左栏点击高亮框，右栏对应卡片滚动到可视区。
6. 展开卡片上的「条款差异对比」查看原文与建议的逐字增删；点击「复制」取走修改建议。
7. 在卡片上「编辑建议」或「采纳」。
8. 底部填写法务批注并「保存批注」。
9. 顶栏点击「预览报告」查看 Markdown 渲染效果；点击「导出报告」选择 Markdown 或 PDF，落存储并下载。
10. 点击「写回审批意见」，将审查意见写入审批系统评论区。

若需调整判定口径，进入右上角「规则配置」修改或新增规则，回到大盘页对目标合同执行「重试」（或同步新待办），新口径即生效。

### 7.2 审查大盘页

- **列表字段**：合同名称、业务类型、申请人、金额、审查状态、风险等级、回写状态、创建时间。
- **筛选**：关键词（前端按合同名称与合同编号匹配）、审查状态、风险等级；列表按页分页展示。
- **同步与上传**：「同步审批待办」从审批系统拉取；「上传合同」支持 `.docx` / `.pdf` / 图片，上传入口当前固定按「采购合同」业务类型入库。
- **行内重试**：仅「阻塞」状态的行出现「重试」按钮，悬停状态标签可查看阻塞原因。
- **批量操作**：勾选任意行后出现操作条，支持批量重试与批量删除；部分失败会逐条列出失败项，不静默忽略。
- **导出记录**：行内图标打开该合同的报告导出历史（含大小 / 导出人 / 下载）。
- **原件下载**：行内「下载原件」直接获取合同文件。

### 7.3 示例合同

`mock-approval` 预置 4 条待办（采购 / 销售 / 服务 / 劳动），点击一次「同步审批待办」即可覆盖四类业务场景：

| 示例 | 目录 | 格式 | 接入方式 |
|---|---|---|---|
| 设备采购合同 | `samples/purchase/` | DOCX | 同步待办 |
| 产品销售合同 | `samples/sales/` | DOCX | 同步待办 |
| 技术服务合同 | `samples/service/` | DOCX | 同步待办 |
| 劳动合同 | `samples/labor/` | DOCX | 同步待办 |
| 设备采购合同（扫描件） | `samples/scanned/` | 无文本层 PDF（走 OCR 链路） | 大盘页手动上传 |

每份样本在 `samples/expected/` 下带有对应的人工标注期望风险点，`scripts/run_tests.py` 会逐条比对，作为回归断言集。

## 8. 配置说明

### 8.1 环境变量

复制 `.env.example` 为 `.env` 后按需修改（`.env` 不纳入版本控制）。关键项：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `MYSQL_PORT` | `13306` | 容器映射端口（不占用本机 3306） |
| `REDIS_PORT` | `16379` | 容器映射端口 |
| `MINIO_PORT` | `19000` | 容器映射端口 |
| `LLM_PROVIDER` | `mock` | `mock` 或 `openai_compat` |
| `LLM_BASE_URL` | 空 | OpenAI 兼容端点，`openai_compat` 时必填 |
| `LLM_API_KEY` | 空 | 同上 |
| `LLM_MODEL` | 空 | 模型名称 |
| `DOCX_CONVERTER` | `wps_com` | DOCX 转 PDF 转换器 |
| `OCR_ENABLED` | `true` | 扫描件与图片是否走 OCR；置 `false` 则直接进入 `blocked` |
| `OCR_DPI` | `200` | OCR 渲染 DPI（越高越准、越慢） |
| `OCR_METADATA_REVIEW_THRESHOLD` | `0.85` | 元数据置信度低于此值标记 `need_review`，工作台提示人工核对 |

### 8.2 LLM 配置

`LLM_PROVIDER=mock` 时使用预置结论回放，**无 LLM 密钥也能跑通完整链路**（解析 → 审查 → 落库 → 报告 → 回写），适用于演示与回归测试。

接入真实模型时设置 `LLM_PROVIDER=openai_compat` 并填写 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`。

### 8.3 环境自检

```powershell
backend\.venv\Scripts\python.exe scripts\check_env.py
```

逐项校验 MySQL / Redis / MinIO / 审批系统连通性与 LLM 配置。可选参数：`--quiet`（仅输出结论）、`--skip-llm`（跳过 LLM 真实调用）。

## 11. 已知限制

| 限制 | 说明 |
|---|---|
| WPS COM 依赖交互式桌面 | 后端不能容器化（无桌面会话时 DOCX 分页失效，走无分页降级） |
| WPS 与 Word 分页可能不一致 | 报告标注"页码基于 WPS 排版" |
| DOCX 转换串行执行 | 同步多条待办时总耗时线性增长（实测 3 份约 4.1s）；并发设计归阶段二 |
| 扫描件 OCR 性能 | 本地 CPU 约 6s/页，二次解析走 Redis 缓存；字符框取自 OCR 字/词级框（均值误差约 2pt），框数与字符数不符的行回退等宽 |
| 扫描件无文本层 | 工作台「点正文文字反查风险卡片」不可用，卡片到正文高亮正常 |
| 合同版本管理未实现 | `contract` 与 `review_task` 为 1:1 关系 |
| 单进程后台线程 | 演示并发为 1；批量审查需迁 Celery（阶段二） |
| 违约责任不对等判定为启发式 | 使用关键词并存判定，不做当事人方向理解：双方同时写入无上限与限额也会命中（误报），冷门措辞表达的不对等会漏报；词表与 `mild_ratio_max` 可在规则库调整 |
| 用户角色与权限未实现 | 全库无 JWT / OAuth2 认证授权，三类角色实际能力相同；`author_role` 仅为批注表字段 |
| 低风险等级当前不产出 | 枚举、UI 与报告配色均支持三级，但现有 45 条规则只产出高 / 中风险；接入真实 LLM 后可能产出 |
| 元数据「生效条件」样本未覆盖 | 正则实现正确，但 5 份样本合同无「生效」字样，该字段为空 |
| `ENCRYPTED` / `BLURRED` 阻塞未实测 | 代码路径存在且有抛出点，当前仅实测了 `EMPTY_CONTENT`，不宣称已验证 |
| 黑名单为演示数据 | 不代表真实工商信息 |
| 风险阈值与结论为拟值 | 非法律意见，可在规则库调整 |

## 12. 故障排查

| 现象 | 排查方向 |
|---|---|
| 启动日志中某项自检失败 | 对应容器未启动：执行 `docker ps`；或 `.env` 端口与实际映射不符 |
| 上传 DOCX 后一直处于「解析中」 | 确认 WPS 能否正常打开该文档；查看后端日志中的转换器降级链 |
| 任务变为 `blocked` | 查看工作台「审查轨迹」或 `GET /api/contracts/{id}/events` |
| 正文区提示「正文无法渲染」 | 该合同尚无转换后 PDF（`pdf_object_key` 为空）；审查结果仍可查看 |
| 上传图片后长时间停留在「解析中」 | 图片走 CPU OCR（约 6s/页）；重复上传同一文件命中缓存会显著加快 |
| 扫描件正文没有文字高亮 | 正常现象：扫描件无 PDF.js 文本层，仅有元数据虚线框与风险高亮 |
| 风险卡片显示「未锚定」标记 | 模型引用无法定位到原文，属防幻觉闸门正常工作，需人工核查 |
| 回写失败 | 查看 `GET /api/contracts/{id}/writeback/status` 的 `error_detail` |
| 前端 `/api` 请求返回 404 | 后端未启动，或 `vite.config.ts` 代理目标端口不正确 |
| 端口被占用（8000 / 8010 / 5173） | 执行 `python scripts\stop_all.py` 收尾；脚本只结束本项目进程，无关进程会跳过并打印其命令行 |
